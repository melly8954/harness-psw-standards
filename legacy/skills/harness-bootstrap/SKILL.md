# Harness Bootstrap

프로젝트가 전역 문서 설계 하네스를 사용할 수 있도록 최소 구조와 연결 규칙을 구성한다.

## 공통 규칙

작업 전에 다음 문서를 읽고 따른다.

- `~/.claude/harness/common-execution-rules.md`
- `~/.claude/harness/harness-structure.md`

## 입력

1. 대상 프로젝트 루트
2. 기존 프로젝트 `CLAUDE.md`
3. 기존 `docs/` 구조와 문서 인덱스
4. 저장소의 실제 기술 구성
5. 기존 문서 참조, 스크립트와 CI 설정
6. 사용자 요청

기존 파일이 있으면 덮어쓰기 전에 내용을 확인한다.

## 책임

- 프로젝트 문서 구조 확인
- 필요한 최소 루트 문서 경로 준비
- 프로젝트 `CLAUDE.md` 생성 또는 최소 보완
- 전역 스킬과 실제 문서 경로 연결
- 단일 문서와 분리형 문서 구조 판별
- 루트 인덱스와 상세 문서 연결 확인
- 파일명, 경로와 선택 로딩 순서 정규화
- 초기 구조 감사 결과 제공

제품 요구사항, 기술 선택, 데이터 모델, API와 UI 계약은 임의로 생성하지 않는다.

## 기본 프로젝트 구조

새 프로젝트는 기본적으로 루트 기준 문서만 준비한다.

```text
프로젝트/
├─ CLAUDE.md
└─ docs/
   ├─ prd.md
   ├─ Architecture.md
   ├─ ERD.md
   ├─ API.md
   ├─ app-design.md
   ├─ coding-convention.md
   └─ decisions.md
```

프로젝트에 필요하지 않은 문서는 강제로 만들지 않는다.

상세 디렉터리와 빈 상세 문서는 미리 생성하지 않는다.

## 확장 문서 구조

기존 프로젝트에 다음 디렉터리가 있으면 지원 구조로 인식한다.

```text
docs/
├─ prd/
├─ architecture/
├─ erd/
├─ api/
├─ app-design/
├─ conventions/
└─ decisions/
```

상세 문서는 문서 규모와 선택적 로딩 필요성이 확인된 경우에만 생성한다.

기존 단일 문서를 사용자의 요청 없이 자동 분리하지 않는다.

## 초기화 절차

1. 프로젝트 루트와 저장소 구조를 확인한다.
2. 기존 `CLAUDE.md`, 루트 문서와 상세 디렉터리를 조사한다.
3. 표준 구조와의 차이를 분류한다.
4. 프로젝트에 필요한 기준 문서를 판단한다.
5. 기존 문서는 보존하고 필요한 루트 문서만 최소 생성한다.
6. 기존 분리형 문서가 있으면 루트 인덱스와 경로를 확인한다.
7. 프로젝트 `CLAUDE.md`에 실제 문서 경로와 선택 로딩 규칙을 작성한다.
8. 프로젝트 전용 금지 사항과 검증 명령이 있으면 연결한다.
9. 빈 문서에는 목적과 미작성 상태만 표시한다.
10. 전역 스킬이 기대하는 경로와 실제 경로가 일치하는지 확인한다.
11. 생성·수정·보존·제외된 파일과 다음 실행 스킬을 보고한다.

## 문서 구조 판단

다음과 같이 판단한다.

```text
문서가 작고 관련 내용을 쉽게 찾을 수 있음
→ 단일 루트 문서 유지

문서가 크거나 기존 상세 문서가 존재함
→ 루트 인덱스와 상세 문서 연결 확인

분리가 필요하지만 사용자 요청이 없음
→ 자동 분리하지 않고 권장안만 보고
```

프로젝트의 기존 구조가 안정적으로 동작하면 표준 구조와 다르다는 이유만으로 변경하지 않는다.

## 프로젝트 CLAUDE.md 기준

프로젝트 `CLAUDE.md`에는 필요한 항목만 둔다.

- 전역 규칙과 프로젝트 규칙의 우선순위
- 실제 기준 문서 목록과 경로
- 루트 문서와 상세 문서의 관계
- 작업별 선택 로딩 규칙
- 프로젝트 전용 작업 제한
- 구현 전 확인 사항
- 검증 명령 또는 완료 조건
- 문서 변경 시 동기화 대상

전역 공통 실행 규칙과 개별 스킬 절차를 복사하지 않는다.

## 선택 로딩 기준

`CLAUDE.md`에는 다음 방향을 반영한다.

```text
현재 작업의 루트 기준 문서
→ 관련 상세 문서
→ 직접 관련된 상위 문서 구간
→ 필요한 경우에만 영향 문서
```

`docs/` 또는 상세 디렉터리 전체를 일괄 로드하도록 작성하지 않는다.

## 빈 문서 처리

누락된 루트 문서가 프로젝트에 필요하면 최소 골격만 생성할 수 있다.

```text
# 문서 제목

이 문서는 아직 작성되지 않았다.

해당 전역 설계 스킬을 사용해 프로젝트 결정에 따라 작성한다.
```

빈 문서에 추정한 제품·기술 내용을 채우지 않는다.

빈 상세 문서와 빈 상세 디렉터리는 만들지 않는다.

## 기존 분리 구조 처리

상세 문서가 이미 존재하면 다음을 확인한다.

- 루트 문서에 상세 문서가 등록되어 있는가
- 실제 경로와 인덱스 경로가 일치하는가
- 상세 문서의 범위가 구분되는가
- 공통 내용이 여러 문서에 중복되지 않는가
- 한 계약이나 결정의 원천이 여러 곳에 존재하지 않는가

명백한 경로 오류 외에는 내용을 임의로 재배치하지 않는다.

## 기존 구조 충돌 처리

다음 상황에서는 자동 변경보다 보고를 우선한다.

- 동일 목적의 문서가 다른 이름으로 존재함
- 문서 간 기준 순서가 이미 다르게 정의됨
- 프로젝트 `CLAUDE.md`가 전역 규칙과 충돌함
- 파일 이동이 외부 도구, 링크나 CI에 영향을 줄 수 있음
- 대소문자 변경이 운영체제 또는 Git에서 위험함
- 기존 단일 문서와 분리 문서에 같은 내용이 중복됨

가능한 변경안과 영향을 제시하고 안전한 최소 변경만 수행한다.

## 출력

- 프로젝트 `CLAUDE.md`
- 필요한 최소 루트 `docs/` 구조
- 확인된 루트·상세 문서 연결 상태
- 생성·수정·보존·제외 파일 목록
- 발견된 충돌, 누락과 중복
- 구조 분리가 필요한 경우 권장안
- 다음에 실행할 권장 설계 스킬

## 완료 검증

- 프로젝트 루트와 실제 문서 경로가 명확한가
- 기존 파일을 불필요하게 덮어쓰지 않았는가
- 프로젝트에 필요한 문서만 준비했는가
- 빈 상세 디렉터리와 문서를 미리 만들지 않았는가
- 프로젝트 규칙과 전역 규칙의 우선순위가 설명되는가
- 루트 문서와 상세 문서의 선택 로딩 기준이 있는가
- 루트 인덱스와 실제 상세 문서가 일치하는가
- 프로젝트 결정을 임의로 생성하지 않았는가
- 전역 스킬이 실제 문서 경로를 사용할 수 있는가
- 충돌과 후속 작업이 명확히 보고되었는가
