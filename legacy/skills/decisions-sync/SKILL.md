# Decisions Sync

중요한 결정 이력을 `docs/decisions.md`와 필요 시 `docs/decisions/` 하위 문서에 정리한다.

```text
docs/
├─ decisions.md
└─ decisions/
   └─ DEC-<number>-<topic>.md
```

- `docs/decisions.md`: 결정 인덱스, 상태와 요약
- `docs/decisions/DEC-<number>-<topic>.md`: 개별 결정의 상세 기록

작은 프로젝트에서는 `docs/decisions.md` 단일 문서를 유지한다.

## 공통 규칙

작업 전에 `~/.claude/harness/common-execution-rules.md`를 읽고 따른다.

## 입력

필요한 항목만 선택해서 읽는다.

1. 프로젝트 `CLAUDE.md`
2. 사용자 요청
3. 변경된 원천 기준 문서
4. 원천 문서가 참조하는 관련 기준 문서
5. 기존 `docs/decisions.md`
6. 관련된 `docs/decisions/DEC-*.md`
7. 변경 diff 또는 사용자가 제공한 결정 내용

모든 기준 문서와 모든 결정 파일을 일괄해서 읽지 않는다.

결정 ID, 주제, 원천 문서 또는 변경 범위를 기준으로 관련 기록만 찾는다.

## 기록 대상

다음 변경은 결정 추적 대상이다.

- 제품 범위와 비범위
- 사용자 역할과 권한
- 상태값, 상태 전이, 삭제·보관 정책
- 기술 스택, 시스템 경계, 인증·배포·저장 전략
- 엔터티 관계, 핵심 제약과 식별자 정책
- 공개 Endpoint, DTO, 오류와 이벤트 계약
- 핵심 사용자 흐름과 접근성 정책
- 구현 전반에 영향을 주는 코드 구조와 도구 정책

오탈자, 표 정렬, 문장 다듬기와 의미가 바뀌지 않는 용어 통일은 기록하지 않는다.

## 문서 분리 기준

기본은 `docs/decisions.md` 단일 문서다.

다음 조건에서는 개별 결정 파일로 분리할 수 있다.

- 기록 수가 많아 관련 결정만 선택해서 읽기 어려움
- 하나의 결정에 배경·대안·전환 계획이 길게 필요함
- 결정별 상태 변경과 대체 관계가 자주 발생함
- 여러 작업이 결정 문서를 동시에 수정함

분리 후 `docs/decisions.md`는 인덱스와 요약만 유지한다.

파일명 예시:

```text
DEC-001-jwt-authentication.md
DEC-002-message-pagination.md
DEC-003-file-storage.md
```

## 작업 모드

- 생성: 중요한 신규 결정 기록을 추가한다.
- 갱신: 기존 결정의 상태, 영향 또는 후속 정보를 수정한다.
- 대체: 이전 결정을 보존하고 `SUPERSEDED` 관계를 연결한다.
- 검증: 원천 문서와 결정 기록의 추적성을 점검한다.
- 분리: 기록 규모상 필요하거나 사용자가 요청한 경우 개별 파일로 분리한다.

`decisions-sync`는 새로운 제품 정책이나 기술 구조를 최초로 결정하지 않는다. 이미 원천 문서에서 확정된 결정을 기록한다.

## 실행 절차

1. 변경된 원천 문서와 결정 내용을 확인한다.
2. 결정 추적 대상인지 판단한다.
3. 기존 관련 결정 ID를 찾는다.
4. 신규, 갱신 또는 대체 여부를 결정한다.
5. 배경, 대안, 이유와 영향을 기록한다.
6. 대체 시 이전 기록을 `SUPERSEDED`로 변경한다.
7. `supersedes`와 `superseded-by`를 연결한다.
8. 원천 문서와 결정 기록의 내용이 일치하는지 검증한다.
9. 영향을 받는 하위 문서와 전환 상태를 기록한다.
10. 인덱스와 상세 문서의 상태를 동기화한다.

## Decisions 고유 원칙

- 결정의 원천은 PRD, Architecture, ERD, API, App Design 또는 Coding Convention이다.
- `decisions.md`만으로 새로운 결정을 만들지 않는다.
- 이전 결정을 삭제하지 않고 상태와 대체 관계로 보존한다.
- 결정 이유와 영향을 결과만큼 중요하게 기록한다.
- 검토한 대안을 모두 장황하게 적지 않고 실제 후보만 기록한다.
- 동일한 결정을 여러 ID로 중복 생성하지 않는다.
- 원천 문서와 다른 표현으로 의미를 변경하지 않는다.
- 관련 없는 결정 기록을 예방적으로 읽거나 수정하지 않는다.

## 결정 기록 기준

각 결정에는 다음 항목을 포함한다.

```text
ID
상태
결정일
원천 문서
결정 내용
배경과 문제
검토한 대안
결정 이유
영향
전환 또는 마이그레이션
supersedes
superseded-by
```

상태는 다음 중 하나를 사용한다.

```text
PROPOSED
ACCEPTED
SUPERSEDED
REJECTED
```

## 기본 문서 구조

### 단일 문서 유지 시 `docs/decisions.md`

```text
1. 문서 목적
2. 기록 규칙
3. 결정 목록
4. 결정 상세
5. 추적성 점검 결과
```

### 개별 파일 분리 시 `docs/decisions.md`

```text
1. 문서 목적
2. 기록 규칙
3. 상태별 결정 인덱스
4. 최근 변경
5. 추적성 점검 결과
```

### `docs/decisions/DEC-*.md`

```text
1. ID와 상태
2. 원천 문서
3. 결정
4. 배경과 문제
5. 검토한 대안
6. 결정 이유
7. 영향
8. 전환 계획
9. 대체 관계
```

## 출력

- 결정 인덱스 또는 단일 기록 문서: `docs/decisions.md`
- 개별 결정 상세: `docs/decisions/DEC-<number>-<topic>.md`
- 새 파일을 만들거나 상태가 바뀌면 인덱스를 갱신한다.
- 원천 문서는 사용자의 요청 범위 안에서만 수정한다.
- 결정 기록만 갱신하고 하위 문서 동기화가 남으면 이를 명시한다.

## 완료 검증

- 변경이 실제 결정 추적 대상인가
- 결정의 원천 문서가 명확한가
- 원천 문서와 결정 내용이 일치하는가
- 신규·갱신·대체 상태가 올바른가
- 대체된 결정을 삭제하지 않았는가
- `supersedes`와 `superseded-by`가 연결되는가
- 배경, 대안, 이유와 영향이 남아 있는가
- `docs/decisions.md` 인덱스와 상세 문서가 일치하는가
- 동일한 결정이 중복 기록되지 않았는가
- 하위 문서 동기화 상태를 설명할 수 있는가
