# Harness Draft

`harness-plan`의 문서 계획에서 `생성` 또는 `갱신`으로 정해진 파일만 초안으로 작성한다. 템플릿은 `harness-init/references/templates/`에서 읽고, 이 단계에서는 대상 프로젝트 파일을 수정하지 않는다.

## 작성 원칙

- 템플릿의 목차는 시작점일 뿐이다. 프로젝트에 해당하지 않는 항목은 제거한다.
- 모든 사실, 경로, 명령, 계약은 조사 근거를 붙인다.
- 코드로 확인 가능한 현재 상태와 요구사항·정책을 구분한다.
- PRD의 사용자 가치·완료 조건, 운영 권한, 보안 정책은 추정으로 작성하지 않는다.
- 기존 문서를 갱신하는 초안은 승인된 범위의 최소 diff를 제시한다.
- 루트 지시서는 문서 내용을 복제하지 않고 선택된 문서의 읽기 조건과 경로만 라우팅한다.

## 문서별 근거

- `prd`: 요구사항 문서와 사용자 확인
- `architecture`, `api`, `erd`: 코드, 설정, 계약, 마이그레이션
- `conventions`, `testing`: 기존 코드, 린터, 테스트, CI
- `operations`, `security`: 실행·배포 설정과 운영·보안 문서
- `decisions`: 근거 간 충돌과 미결 질문

## 출력 계약

파일별 초안에 대상 경로, 처리 방식, 사용 템플릿, 본문, 근거, 남은 확인 필요 사항을 붙여 출력한다.
