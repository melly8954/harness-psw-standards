# Harness Secrets

환경 변수, 인증 정보, API Key, 토큰 등 민감 정보를 다룰 때의 기본 원칙을 정의한다. 이 규칙은 전체 하네스 과정에도 적용한다.

## 기본 원칙

- 실제 시크릿을 코드나 문서에 직접 기록하지 않는다.
- `.env` 등의 로컬 환경 파일을 임의로 커밋하지 않는다.
- 필요한 환경 변수의 이름과 목적은 예제 또는 별도 문서로 관리할 수 있다.
- 예제 값과 실제 인증 정보를 명확히 구분한다.
- 기존 시크릿을 로그, 테스트 출력, 문서 등에 노출하지 않는다.
- 실제 값이 확인되지 않았을 때 임의의 운영 값을 만들지 않는다.
- 테스트·예제에 민감 정보와 혼동될 수 있는 실제 형태의 값을 불필요하게 사용하지 않는다.
- 시크릿 저장소나 배포 환경의 값을 임의로 변경하지 않는다.

필요하면 `.env.example`, 배포 문서 또는 보안 문서로 상세 내용을 라우팅한다.

## 조사와 판단

예제 설정, ignore 규칙, 변수 이름, 배포·CI의 시크릿 참조, 보안 문서를 확인한다. 실제 시크릿 값이나 민감한 설정 본문은 읽어 출력·기록하지 않는다.

확인된 파일 위치, 변수의 목적, 시크릿 저장소의 경계만 반영한다. 새 변수의 값, 운영 시크릿 변경, 저장소 선택처럼 권한·보안에 영향을 주는 항목은 정하지 않고 질문 후보로 남긴다.

## 출력과 중단

`사실`, `근거`, `지시서 반영`, `생략`, `확인 필요`와 안전 규칙·관련 파일 경로를 출력한다. 실제 시크릿이나 운영 값을 추정·노출·변경하지 않는다.
