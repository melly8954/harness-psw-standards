# Harness Verification

변경 결과가 기술적으로 정상이고 프로젝트 요구사항과 사용자 시나리오를 충족하는지 확인할 기준을 정의한다.

## 기술 검증

프로젝트에 실제 존재하는 항목만 포함한다.

- 빌드 명령
- 단위·통합 테스트
- 린트·포맷 검사·타입 검사·정적 분석
- 변경 영역 실행 확인
- 변경 유형별 필수 검증
- 수행할 수 없는 검증의 보고 방법

## QA

프로젝트 절차가 있을 때만 다음을 반영한다.

- 주요 사용자 시나리오와 E2E 테스트
- 수동 확인·회귀 테스트
- 브라우저·OS·디바이스별 확인
- 기능별 인수 조건 또는 완료 기준
- 릴리즈 전 QA 기준

별도 QA 절차가 없으면 기술 검증에 통합할 수 있다. 실제로 수행 가능한 검증 방법과 확인된 명령만 지시서에 포함한다.

## 조사와 판단

빌드 설정, 패키지 스크립트, 테스트 디렉터리, CI 워크플로, 기존 검증 문서를 대조한다. 명령 정의가 존재하는 것과 실제 실행해 통과한 것은 구분한다.

변경 유형별 최소 검증 기준은 기존 CI·문서·테스트 관례로 확인될 때만 반영한다. 검증 수준을 선택해야 하는데 근거가 없거나, 실행 시간·외부 의존성 때문에 수행 가능 여부가 달라지면 질문 후보로 남긴다.

## 출력과 중단

`사실`, `근거`, `지시서 반영`, `생략`, `확인 필요`와 함께 명령, 적용 조건, 미확인 검증을 명시한다. 실행해 보지 않았거나 존재하지 않는 명령을 통과 결과로 쓰지 않는다.
