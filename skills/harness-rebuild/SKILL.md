# Harness Rebuild

기존 `AGENTS.md`, `CLAUDE.md`, 하위 지시서와 관련 문서를 안전하게 재구축하는 전용 오케스트레이터다. 신규 하네스 구축에는 사용하지 않고 `$harness-init`을 사용한다.

## 고정 실행 순서

1. 현재 하네스 감사
2. 목표 문서 트리와 마이그레이션 계획 작성
3. 문서·라우팅·링크의 재구축 초안 작성
4. 내용 보존·링크 영향·삭제 후보 검토와 사용자 인터뷰
5. 사용자 승인 후 반영

각 단계의 결과를 다음 단계에 전달한다. 조사·계획·초안·검토 단계에서는 대상 프로젝트 파일을 수정하지 않는다.

## 감사

다음을 근거와 함께 조사한다.

- 기존 지시서와 하위 문서의 역할·적용 범위·상호 링크
- 중복 규칙, 누락 문서, 오래된 경로·명령·정책
- 문서별 실제 내용 소유권과 코드·설정·CI와의 충돌
- 이동·병합·삭제 시 영향을 받는 링크와 참조자

실제 시크릿과 운영 값은 출력하지 않는다. 기존 문서가 잘못됐다고 추정만으로 판단하지 않고, 근거와 영향 범위를 기록한다.

## 마이그레이션 계획

각 문서를 아래 중 하나로 분류한다.

- `유지`: 현재 경로와 소유권을 유지한다.
- `갱신`: 같은 경로에서 최소 변경한다.
- `생성`: 필요한 소유 문서가 없을 때 만든다.
- `병합`: 여러 문서의 보존할 내용을 하나로 통합한다.
- `이동`: 역할과 경로를 바꾸고 참조 링크를 갱신한다.
- `폐기 후보`: 중복·오류 문서이지만 삭제 승인 전에는 유지한다.

계획에는 `현재 경로`, `대상 경로`, `처리`, `보존할 내용`, `근거`, `링크 영향`, `확인 필요`를 포함한다. `harness-init/references/templates/`는 목표 문서의 최소 골격으로만 사용한다.

## 검토와 승인

병합·이동 대상은 원본에서 보존한 내용과 갱신할 링크를 초안에 명시한다. 근거가 없거나 답변에 따라 결과가 달라지는 사항만 한 번에 질문한다.

일반 반영 목록과 폐기 후보를 분리해 제시한다. 폐기 후보마다 삭제할 정확한 경로, 대체·보존 위치, 링크 영향을 명시하고, 파일별 삭제 승인을 받기 전에는 삭제하지 않는다.

## 반영

일반 승인을 받은 생성·갱신·병합·이동만 반영한다. 폐기 후보는 파일별 삭제 승인까지 받은 경우에만 제거한다.

최종 결과에는 반영·유지·삭제한 파일, 보존 위치, 갱신한 링크, 수행한 검증과 미검증 사항을 보고한다.
