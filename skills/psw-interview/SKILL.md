# psw-interview

SRS를 쓰기 위한 재료를 모은다. SRS 자체는 `psw-srs`가 쓴다.

## 입력과 출력

| 입력 | 출력 |
|---|---|
| 프로젝트 주제 (사용자) | `records/references/<slug>.md` |
| 기존 인터뷰 기록, SRS (다시 묻는 경우) | `records/interviews/YYYY-MM-DD.md` |
| | OPEN (`psw-change` 절차 A) |

## 규칙

- 질문 목록과 순서: `references/checklist.md`
- 한 번에 3~5개씩 묻는다
  → 한꺼번에 많이 물으면 답이 얕아진다
- 질문마다 선택지와 추천안을 함께 제시한다
- 모르는 답은 추측하지 않는다. `psw-change` 절차 A로 OPEN을 등록하고 다음 질문으로 넘어간다
  - OPEN 본문에 체크리스트 ID를 적는다
- 해당 없는 항목은 답을 "해당 없음"으로 기록한다. `psw-srs`가 SRS `02-scope`의 해당 없음 목록에 옮긴다
- 답은 뜻이 바뀌지 않게 원문에 가깝게 기록한다. 기록 형식: `references/interview.md`
- 인터뷰 중 SRS나 REQ 파일을 직접 고치지 않는다

## 절차

### 1. 시작

- 새 프로젝트면 주제를 확인한다. 사용자가 주제를 말하지 않았으면 묻는다
- 다시 묻는 경우(누락 보완, OPEN 해결)면 `checklist-coverage.sh` 결과나 해당 OPEN부터 확인하고 3단계로 간다

### 2. 레퍼런스 조사

1. 주제와 비슷한 서비스·사례를 1~2개 고른다
   - 웹 검색을 쓸 수 있으면 출처를 확인한다. 확인하지 못한 내용은 "확인되지 않은 정보"에 적는다
   - 원문을 옮기지 않고 요약한다
2. `records/references/<slug>.md`를 작성한다. 형식: `references/reference.md`
3. 레퍼런스의 기능을 후보로 제시하고, 사용자가 채택·제외·보류를 고르게 한다
   - 제외한 기능은 SRS 범위 밖으로 간다
   - 보류한 기능은 OPEN으로 등록한다

### 3. 인터뷰

1. 체크리스트 순서대로 묻는다: 방향성 → 행위자 → 기능 → 비기능·보안·연동·데이터 → 제약
   → 기능이 나와야 비기능의 적용 범위가 정해진다
2. 기능(ck-fun-2, ck-fun-3)은 도메인마다 반복해서 묻는다
3. 묶음마다 답을 인터뷰 기록에 남긴다. 같은 날 다시 하면 파일 끝에 세션을 이어 붙인다

### 4. 마무리

1. `.claude/scripts/psw/checklist-coverage.sh`를 실행한다
2. 누락된 `[필수]` 항목이 있으면 이어서 묻는다
3. 결과를 보고한다
   - 모은 답의 요약 (영역별)
   - 등록한 OPEN
   - 다음 단계: `psw-srs`로 SRS를 작성한다

## 커밋

- 인터뷰 기록과 레퍼런스는 `records/` 변경이므로 트레일러가 필수가 아니다
- 메시지 예: `docs: 기획 인터뷰 기록 (방향성, 행위자)`
