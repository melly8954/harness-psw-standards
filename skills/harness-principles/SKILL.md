# Harness Principles

프로젝트에 관계없이 에이전트가 작업할 때 따라야 할 공통 행동 기준을 정의한다. 이 규칙은 전체 하네스 과정에도 적용한다.

## 포함할 수 있는 원칙

- 작업 전 기존 구조와 의도를 우선 확인한다.
- 요청 범위를 넘어 기능·정책·구조를 임의로 확장하지 않는다.
- 변경 전후 영향 범위를 확인한다.
- 기존 문서·코드·테스트와의 정합성을 확인한다.
- 작업 중 발견한 별도 문제를 현재 요청 범위와 구분한다.
- 프로젝트 내부 규칙이나 지시가 충돌하면 임의로 한쪽을 선택하지 않고, 명시된 우선순위나 더 구체적인 범위를 확인한다.

구체적인 프로젝트 정책이 있으면 전문을 복사하지 말고 해당 문서로 라우팅한다.

## 조사와 판단

루트와 하위의 기존 지시서, 기여 안내, 팀 정책 문서를 확인해 적용 범위와 우선순위를 찾는다. 공통 행동 원칙과 특정 언어·모듈·도구에만 적용되는 규칙을 분리한다.

확인된 공통 원칙은 초안에 반영한다. 우선순위가 없거나 서로 충돌하는 규칙은 임의로 통합하지 않고 차이와 영향 범위를 질문 후보로 남긴다. 확인되지 않은 조직 정책은 일반 원칙처럼 추가하지 않는다.

## 출력과 중단

`사실`, `근거`, `지시서 반영`, `생략`, `확인 필요`와 공통 원칙 초안을 출력한다. 충돌 우선순위가 확인되지 않으면 임의의 우선순위를 만들지 않는다.
