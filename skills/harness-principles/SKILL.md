# Harness Principles

프로젝트에 관계없이 에이전트가 작업할 때 따라야 할 공통 행동 기준을 정의한다. 이 규칙은 전체 하네스 과정에도 적용한다.

## 포함할 수 있는 원칙

- 작업 전 기존 구조와 의도를 우선 확인한다.
- 요청 범위를 넘어 기능·정책·구조를 임의로 확장하지 않는다.
- 변경 전후 영향 범위를 확인한다.
- 기존 문서·코드·테스트와의 정합성을 확인한다.
- 작업 중 발견한 별도 문제를 현재 요청 범위와 구분한다.
- 프로젝트 내부 규칙이나 지시가 충돌하면 임의로 한쪽을 선택하지 않고, 명시된 우선순위나 더 구체적인 범위를 확인한다.

구체적인 프로젝트 정책이 있으면 전문을 복사하지 말고 해당 문서로 라우팅한다.

## 출력과 중단

공통 원칙 초안과 근거를 출력한다. 충돌 우선순위가 확인되지 않으면 임의의 우선순위를 만들지 않는다.
