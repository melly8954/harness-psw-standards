# Harness Review

문서 계획과 초안을 대조해 승인 가능한 검토 패키지를 만든다. 이 단계에서는 대상 프로젝트 파일을 수정하지 않는다.

## 검토 항목

- 계획된 파일만 초안으로 존재하는지
- 경로·명령·API·데이터 모델·정책에 근거가 붙어 있는지
- 기존 문서와 중복하거나 충돌하는 내용을 새로 만들지 않았는지
- 실제 시크릿, 운영 값, 권한 없는 배포 절차를 포함하지 않았는지
- 루트 지시서가 상세 문서를 복제하지 않고 올바른 경로로 라우팅하는지

## 인터뷰 규칙

요구사항, 완료 조건, 문서 소유권, 운영 권한처럼 답변에 따라 계획이나 본문이 달라지는 항목만 질문한다. 안전하게 생략할 수 있는 항목은 질문하지 않고 생략한다.

질문은 문서별로 흩어 놓지 말고 한 번에 묶는다. 답변을 반영한 뒤 생성·갱신할 파일 목록과 최종 초안을 제시하고 명시적 승인을 받는다.

## 출력 계약

`반영 예정`, `기존 문서 사용`, `생략`, `확인 필요`, `검증 결과`를 구분한 검토 패키지를 출력한다.
