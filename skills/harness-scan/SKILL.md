# Harness Scan

이 스킬은 문서 생성 계획의 근거 목록만 만든다. 관례나 추측으로 경로·명령·정책을 채우거나 대상 프로젝트 파일을 수정하지 않는다.

## 조사 항목

- 프로젝트 목적, 사용자·도메인 요구사항, 모듈 경계, 최상위 README
- 기존 `AGENTS.md`, `CLAUDE.md`, 문서 색인과 `docs/`의 소유 문서
- API 정의·라우팅·이벤트 계약, 데이터 모델·마이그레이션·스키마
- 아키텍처·인프라·외부 연동의 코드와 설정
- 빌드·테스트·린트·실행 명령, 패키지·빌드 설정, CI
- 로컬 의존 서비스, 배포·운영 문서와 책임 경계
- Git 상태, CONTRIBUTING, 브랜치·PR·커밋 안내
- `.env.example`, ignore 규칙, 설정 문서와 시크릿 관리 진입점

## 조사와 판단

실행 설정·CI·코드는 기술적 사실의 근거로, 요구사항·정책을 소유한 문서는 작업 방식의 근거로 우선 확인한다. 근거끼리 충돌하면 어느 하나를 정답으로 선택하지 않고 차이와 영향 범위를 기록한다.

조사 결과는 문서 영역별로 `사실`, `근거`, `기존 소유 문서`, `부족한 문서`, `확인 필요`를 구분한다. 값이나 권한처럼 조사만으로 안전하게 결정할 수 없는 항목은 질문 후보로 남긴다.

## 출력 계약

각 사실에 근거 파일 경로를 붙여 `PRD`, `architecture`, `API`, `ERD`, `conventions`, `testing`, `operations`, `security`, `decisions`, 루트 지시서에 필요한 정보를 정리한다. 근거가 없거나 충돌하는 항목은 `확인 필요`로 남긴다.

실제 시크릿 값은 읽어 출력하거나 기록하지 않는다. 조사 단계에서는 대상 프로젝트 파일을 수정하지 않는다.
