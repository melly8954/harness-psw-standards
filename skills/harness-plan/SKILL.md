# Harness Plan

`harness-scan`의 근거 목록과 `harness-init/references/templates/`를 바탕으로, 이 프로젝트에 필요한 문서와 각 문서의 소유 위치를 결정한다. 이 단계에서는 대상 프로젝트 파일을 수정하지 않는다.

## 문서 계획 원칙

- 기존 문서가 특정 주제를 명확히 소유하면 새 템플릿 문서를 만들지 않는다.
- 근거가 충분하지만 소유 문서가 없는 주제만 템플릿으로 새 문서 생성 후보로 둔다.
- 코드만으로 확정할 수 없는 PRD·정책·운영 권한은 생성 후보가 아니라 `확인 필요`로 둔다.
- 프로젝트에 해당 영역이 없으면 폴더나 빈 문서를 만들지 않는다.
- 루트 `AGENTS.md` 또는 `CLAUDE.md`는 선택된 문서를 작업 유형별로 연결하는 라우터로만 계획한다.

## 출력 계약

아래 정보를 가진 문서 계획을 출력한다.

| 대상 경로 | 처리 | 템플릿 또는 기존 문서 | 근거 | 확인 필요 |
| --- | --- | --- | --- | --- |
| `docs/architecture/overview.md` | 생성 | `harness-init/references/templates/docs/architecture/overview.md` | 구성·코드 경로 | 없음 |

`처리`은 `생성`, `갱신`, `기존 문서 사용`, `생략` 중 하나만 사용한다. 계획에 없는 파일은 이후 단계에서 작성하거나 반영하지 않는다.
