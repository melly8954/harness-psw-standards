# Harness Git

기존 변경을 보존하고 충돌을 피하는 원칙부터 커밋·브랜치·push·PR 정책까지 하나의 Git 작업 규칙으로 정의한다. Git 작업을 수행하지 않는 프로젝트는 이 섹션을 생략할 수 있다.

## 포함할 수 있는 내용

- 에이전트의 커밋 수행 여부
- 요청받지 않은 기존 변경을 되돌리거나 덮어쓰지 않는 기준
- 관련 없는 파일 수정과 대규모 자동 포맷을 피하는 기준
- 현재 작업과 다른 변경을 구분하고 충돌 가능 파일의 범위를 확인하는 기준
- 커밋 단위와 메시지 규칙
- 관련 없는 변경 포함 금지
- 하나의 커밋에 서로 다른 목적의 변경을 혼합하지 않는 기준
- 자동 생성 문구 또는 특정 trailer 사용 여부
- push 수행 여부
- PR 생성 여부와 범위

커밋·브랜치·PR의 상세 협업 정책이 별도 문서에 있으면 그 문서로 라우팅한다.

## 조사와 판단

현재 Git 상태와 변경 범위, `CONTRIBUTING`·개발 문서·CI의 Git 안내를 확인한다. 작업 트리에 있는 변경은 현재 요청과 다른 변경일 수 있으므로 소유자나 의도를 추정하지 않는다.

명시 정책이 있는 변경 보존·브랜치·커밋 규칙은 반영한다. 에이전트의 커밋·push·PR 수행 권한 또는 충돌 변경의 처리 방침이 불명확하면 질문 후보로 남긴다. 권한이 확인되지 않으면 수행하지 않는 것으로 둔다.

## 출력과 중단

`사실`, `근거`, `지시서 반영`, `생략`, `확인 필요`와 확인된 Git 규칙을 출력한다. 명시 정책이 없으면 에이전트가 커밋·push·PR을 수행한다고 가정하지 않는다.
