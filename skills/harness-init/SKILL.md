# Harness Init

프로젝트 하네스는 루트 지시서 하나가 아니라, 에이전트가 읽을 프로젝트 문서 기반과 이를 연결하는 경량 진입점으로 구성한다. `references/templates/`는 생성 가능한 문서 구조를 정의하고, 프로젝트의 실제 근거가 선택·내용·경로를 결정한다.

단계 이름만 나열하고 실제 결과 없이 완료했다고 보고하지 않는다. 각 단계의 산출물을 다음 단계에 전달한다.

## 작성 원칙

- 현재 프로젝트의 구조와 실제 존재하는 문서를 기준으로만 내용을 구체화한다.
- 프로젝트 성격·규모·기술 스택·운영 방식에 맞는 섹션만 선택한다.
- 확인되지 않은 제품·비즈니스 정책을 만들지 않는다.
- 특정 에이전트에만 해당하는 동작은 공통 규칙과 구분한다.
- 지시서는 작고 안정적으로 유지하며, 상세 문서를 그대로 복제하지 않는다.

## 고정 실행 순서

한 번의 하네스 구축에서는 아래 단계를 순서대로 적용한다. 조사·계획·초안·검토 단계에서는 대상 프로젝트 파일을 수정하지 않는다.

1. `harness-scan` — 프로젝트 사실과 근거 수집
2. `harness-plan` — 문서 트리와 파일별 처리 계획 결정
3. `harness-draft` — 선택된 문서의 근거 기반 초안 작성
4. `harness-review` — 초안 검증과 인터뷰 질문 일괄 정리
5. 사용자 승인 — 생성·갱신할 파일 목록과 초안 승인
6. `harness-compose` — 승인된 모든 문서와 루트 지시서 반영

개별 `harness-*` 스킬은 특정 단계만 다시 검토할 때 직접 사용할 수 있다. 전체 구축에서는 반드시 위 순서를 유지한다.

## 판단과 인터뷰

근거가 있는 내용만 문서 초안에 반영한다. 근거가 없고 안전하게 생략할 수 있는 문서는 만들지 않는다. 요구사항·권한·운영 정책처럼 프로젝트 작업 방식에 영향을 주는 미확인·충돌 항목만 한 번에 사용자에게 질문한다.

기존 문서가 해당 주제를 소유하면 새 문서를 중복 생성하지 않고 그 문서를 계획에 연결한다. 기존 문서가 없고 근거가 충분한 주제만 템플릿을 사용해 새 문서로 만든다.

## 반영 규칙

`harness-review`가 생성·갱신·기존 문서 사용·생략 목록과 초안을 먼저 제시한다. 사용자가 명시적으로 승인한 경우에만 `harness-compose`가 계획된 `AGENTS.md`, `CLAUDE.md`, `docs/*`를 함께 생성·갱신한다.
