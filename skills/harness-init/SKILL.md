# Harness Init

`../../standard_v0.md`를 먼저 읽어 하네스의 정본 기준을 확인한다. 파일이 없으면 기준을 추정하지 말고 설치 상태를 확인하도록 요청한다.

## 흐름

1. 대상 프로젝트와 생성·수정할 지시서 파일의 범위를 확인한다.
2. `harness-scan` 절차로 사실 목록을 만든다.
3. `harness-scope`부터 `harness-secrets`까지의 절차를 적용한다. 섹션별 생략 여부와 근거를 남긴다.
4. `harness-compose` 절차로 검증 가능한 초안을 만든다.
5. 초안, 확인이 필요한 사항, 수행하지 못한 검증을 보고한다.

## 가드레일

- 조사와 초안 작성 단계에서 대상 프로젝트 파일을 수정하지 않는다.
- 확인되지 않은 명령, 경로, 정책을 최종 지시서에 넣지 않는다.
- 최종 파일 반영은 사용자가 초안을 검토하거나 명시적으로 반영을 요청한 뒤에만 수행한다.
