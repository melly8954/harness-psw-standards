# Harness Implementation

코드 구현·수정·리팩터링 시 따를 프로젝트 수준의 기본 규칙을 정의한다. 세부 코딩 컨벤션 전체를 지시서에 복제하지 않는다.

## 포함할 수 있는 내용

- 프로젝트의 주요 구현 원칙
- 계층 또는 모듈 간 책임 경계
- 신규 코드 작성 시 기존 구조를 우선 따르는 기준
- 공통 컴포넌트·유틸리티·추상화 재사용 기준
- 불필요한 의존성이나 새로운 패턴 도입 제한
- 세부 구현 규칙 문서의 진입점

예를 들어 세부 Java 규칙은 `docs/conventions/java.md`, API 구현 규칙은 `docs/conventions/api.md`, React 규칙은 `docs/conventions/frontend.md`처럼 실제 존재하는 문서로 연결한다.

프로젝트별 세부 구현 규칙은 관련 문서가 소유하고, 지시서에는 작업 판단에 필요한 핵심 원칙과 진입점만 둔다.

## 출력과 중단

실제 기술 스택, 모듈 경계, 코드 소유권, 기존 컨벤션을 근거로 초안과 참조 문서를 출력한다. 확인되지 않은 기술 규칙을 새로 정의하지 않는다.
