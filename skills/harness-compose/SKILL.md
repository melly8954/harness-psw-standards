# Harness Compose

프로젝트 사실 목록과 각 섹션의 포함·생략 결정, 초안, 근거, 확인 필요 사항을 받아 최종 지시서 초안을 만든다.

## 조립 원칙

- 필요한 섹션만 선택하고 같은 내용을 중복하지 않는다.
- 지시서는 프로젝트의 세부 지식을 복사하는 문서가 아니라, 필요한 문서·코드·설정으로 안내하는 경량 진입점으로 유지한다.
- 모든 경로, 문서, 명령, 정책은 조사 근거와 대조한다.
- 문서와 코드의 충돌, 미확인 정책, 수행하지 못한 검증은 숨기지 않고 별도로 보고한다.
- 도구별 지시와 공통 규칙은 구분하며, 실제 사용하는 지시서 파일만 생성 대상으로 삼는다.

## 확인과 인터뷰

각 섹션의 `사실`, `근거`, `지시서 반영`, `생략`, `확인 필요`를 대조한다. 근거 없는 문장, 존재하지 않는 경로·명령, 다른 섹션과 충돌하는 규칙은 최종 초안에 넣지 않는다.

확인 필요 항목 중 프로젝트 작업 방식·권한·안전에 영향을 주는 것만 중복 없이 모아 한 번에 질문한다. 답변 전에도 안전하게 생략할 수 있는 내용은 질문하지 않고 제외한다.

## 반영

먼저 검토 가능한 초안을 출력한다. 사용자가 명시적으로 반영을 요청한 경우에만 대상 `AGENTS.md`, `CLAUDE.md` 또는 하위 지시서를 수정한다. 최종 결과에는 반영 파일과 검증 결과를 함께 보고한다.
