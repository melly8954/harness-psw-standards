# Harness Operations

프로젝트의 실행 환경과 배포·운영 작업에 필요한 기본 원칙을 정의한다.

## 실행

- 로컬 실행 방법
- 필요한 선행 서비스 또는 의존 시스템
- 개발 환경 구성 방법
- 기본 실행 명령
- 실행에 필요한 프로파일 또는 설정

## 배포

- 개발·스테이징·운영 환경 구분
- 빌드·배포 절차와 CI/CD 파이프라인
- 배포 대상과 책임 범위
- 데이터베이스 마이그레이션 순서
- 배포 전후 검증과 롤백 방법

## 운영

- 운영 환경에서 직접 수행해서는 안 되는 작업
- 운영 변경 시 주의사항
- 로그·모니터링·장애 대응 진입점
- 운영 관련 별도 문서 위치

배포·운영을 직접 담당하지 않는 레포라면 이 섹션을 생략하거나 다른 시스템과의 책임 경계만 명시한다. 상세 절차는 관련 문서에 두고, 지시서에는 작업 중 알아야 할 핵심 원칙과 진입점만 둔다.

## 조사와 판단

실행 설정, 컨테이너·인프라 구성, CI/CD 워크플로, 배포·운영 문서를 확인해 이 레포의 운영 소유 범위와 환경별 책임을 판단한다. 개발·스테이징·운영 환경의 차이는 근거가 있을 때만 적는다.

배포 승인, 운영 접근 권한, 롤백 절차처럼 실행 권한에 영향을 주는 항목은 확인되지 않으면 질문 후보로 남긴다. 운영을 소유하지 않는 레포에는 추정한 배포 절차를 넣지 않는다.

## 출력과 중단

`사실`, `근거`, `지시서 반영`, `생략`, `확인 필요`와 실행·운영 초안을 출력한다. 운영 절차가 확인되지 않으면 섹션을 생략하거나 확인 필요로 둔다.
