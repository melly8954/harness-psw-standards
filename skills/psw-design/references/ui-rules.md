# UI 규칙

- 테마와 컴포넌트의 값은 프론트 코드가 정본이다. 여기에는 값을 적지 않는다
- 테마·컴포넌트 경로와 키트 버전: `docs/design/architecture.md` UI 절
- 커스터마이즈는 테마 변수로만 한다. 컴포넌트 코드의 스타일을 직접 바꾸지 않는다
- 여기에는 화면을 그릴 때의 규칙만 둔다. 프론트 코드 규칙은 `docs/design/conventions.md` 프론트 절이 소유한다

## 테마 사용 규칙

- <예: 색은 테마 변수(primary, destructive 등)의 Tailwind 클래스만 쓰고 원색 값을 직접 쓰지 않는다>

## 레이아웃 규칙

### 간격 단계

<!-- 화면마다 간격이 섞이지 않게 쓰는 단계를 정한다. 표에 없는 간격은 쓰지 않는다 -->

| 단계 | 값 | 쓰는 곳 |
|---|---|---|
| <좁게> | <gap-2> | <버튼 묶음, 아이콘과 글자> |
| <보통> | <gap-4> | <폼 필드 사이, 카드 안> |
| <넓게> | <gap-8> | <페이지의 큰 덩어리 사이> |

### 화면 종류별 본문 폭

| 화면 종류 | 본문 폭 | 예 |
|---|---|---|
| <폼·상세> | <max-w-2xl> | <로그인, 설정> |
| <목록·피드> | <max-w-3xl> | <게시물 목록> |
| <관리 표> | <max-w-6xl> | <운영자 화면> |

## 반응형 규칙

<!-- 기준 폭을 정한 NFR이 있으면 그 값을 쓰고 frontmatter refs에 ID를 적는다 (harness-psw 4.4). 메뉴 체계마다 기준이 다르면 체계별로 나눈다 -->

### 기준점

| 폭 | 이름 | 뜻 |
|---|---|---|
| <360px> | <최소> | <가로 스크롤 없이 보여야 하는 가장 좁은 폭> |
| <768px (`md`)> | <모바일 경계> | <이 폭 미만이 모바일. 셸의 서랍 전환 기준과 같다> |
| <1280px> | <데스크톱> | <관리 화면의 기준 폭> |

### 화면 종류별 좁은 폭 변환

| 요소 | 기준점 이상 | 기준점 미만 |
|---|---|---|
| <셸 메뉴> | <사이드바 또는 상단 메뉴> | <헤더 버튼으로 여는 서랍> |
| <표> | <Table> | <카드 목록. 가로 스크롤로 버티지 않는다> |
| <편집·미리보기> | <나란히 두 칸> | <Tabs로 전환> |
| <폼 버튼 묶음> | <오른쪽 정렬 한 줄> | <세로로 쌓고 폭 100%> |
| <터치 대상> | <기본 크기> | <44×44px 이상> |

### 폭별 목업 확인

- <예: 이용자 화면 목업은 360px에서 가로 넘침을 검사한다 (키트의 넘침 검사)>
- <예: 관리자 화면은 1280px 미만을 지원하지 않는다. 좁은 폭 변환을 적용하지 않는다>

## 상태 표시 규칙

- 빈 상태: <점선 테두리 안내 + 다음 행동 Button>
- 로딩: <Skeleton, 300ms 이상일 때만 표시>
- 오류: <Alert destructive, 다시 시도 Button 포함>

## 문구 규칙

- <예: 버튼은 동사로 끝낸다. 용어는 glossary.md를 따른다>
- 메시지 키: <다국어 요구사항이 있을 때만. 예: 화면 문구는 메시지 파일의 키로 둔다. 키는 <화면 영역>.<요소> 형식, 기본 언어 ko. 파일 위치는 architecture.md UI 절. 목업은 기본 언어로 그린다>
