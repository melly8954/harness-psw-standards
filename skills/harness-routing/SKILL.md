# Harness Routing

프로젝트 지시서는 현재 작업에 필요한 정보를 효율적으로 탐색하도록 안내한다.

## 라우팅 원칙

- 지시서는 경량 라우터로 유지하고 `docs`의 상세 본문을 복사하지 않는다.
- 모든 문서를 미리 읽게 하지 않고, 목적·대상·영향 범위를 기준으로 필요한 문서만 on-demand로 읽게 한다.
- 작업이 여러 문서 영역에 걸치면 필요한 문서를 조합해 확인한다.
- 정보가 부족하면 제품·비즈니스 정책을 임의로 결정하지 않는다.
- 문서와 코드가 충돌하면 어느 한쪽을 자동으로 최신 또는 정답으로 간주하지 않는다. 결과에 영향을 주는 충돌은 차이와 확인 필요 사항으로 다룬다.
- 자동 로드 여부 같은 도구별 동작은 공통 규칙과 섞지 않고 해당 도구 지시서에서 다룬다.

## 문서 지도

세부 문서 전체 목록이 아니라 문서 영역과 주요 진입점을 정의한다. 위치가 불명확할 때만 프로젝트의 문서 색인을 우선 사용한다. 아래는 예시이며 존재하는 영역만 반영한다.

| 필요한 정보 | 문서 영역 예시 |
| --- | --- |
| 요구사항·기능 동작·도메인 규칙 | `docs/prd/` |
| API·외부 계약 | `docs/api/` |
| 시스템 구성·데이터 흐름 | `docs/architecture/` |
| 데이터 모델 | `docs/erd/` |
| 구현·코딩 규칙 | `docs/conventions/` |
| 디자인 시스템·UI 규칙 | `docs/design/` |
| 테스트·검증·QA | `docs/testing/` |
| 보안·인증·권한 | `docs/security/` |
| 실행·배포·운영 | `docs/deployment/` |
| 결정 기록·용어·미결 사항 | `docs/decisions/`, `docs/glossary.md`, `docs/open-questions.md` |

존재하지 않는 경로나 문서를 만들지 않으며, 이름보다 각 영역의 책임을 기준으로 라우팅한다.

## 계층형 라우팅

문서가 많으면 루트 지시서는 최상위 라우터만 담당하고, 영역별 `README.md`를 하위 라우터로 사용한다.

```text
프로젝트 지시서 → docs/README.md → 영역 README.md → 세부 문서
```

상위 README를 읽었다고 하위 문서를 모두 읽게 하지 않는다. 문서 분리는 실제 규모가 필요해졌을 때만 수행한다.
